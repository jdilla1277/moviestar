# Better timing. Cleaner edits. — Moviestar v0.8.2

Moviestar v0.8.2 fixes audio alignment, scene export timing, text layout, and
canvas changes reported during real editing. The package and skills-only plugin
share version 0.8.2.

## Upgrade

For local editing with speech recognition:

```sh
python -m pip install --upgrade 'moviestar[transcribe]==0.8.2'
moviestar --version
moviestar doctor
```

For supplied captions, explicit `--no-transcribe` editing, or account metadata:

```sh
python -m pip install --upgrade 'moviestar==0.8.2'
```

The installation profiles introduced in v0.8.1 still apply. Local media editing
requires FFmpeg and ffprobe; Python 3.10 or newer is required. This release adds
`uharfbuzz` to the base package for font measurement. No new font files are
bundled. Existing project files need no migration, but text can wrap differently
because it is now measured using the selected font. Check rendered proof frames
before delivering an existing edit. See [font measurement](../font-metrics.md)
and [installation profiles](../installation.md).

## Audio that stays on the intended timeline

- Preserve source-audio timing through mixing and normalization, including
  timestamp offsets, so audio does not shift or end early.
- Render routed audio across multiple surviving source windows with FFmpeg's
  supported concatenation filter. Preserve AAC priming and sample-clock timing
  through the segment-renderer path as well.
- With the transcription extra installed, `--no-download` can load an audio
  track with no detected speech without requiring a cached Whisper model.
  Speech still requires a cached model; `--no-speech-check` bypasses detection
  and retains that requirement. A video with no audio stream remains supported
  by the base installation.
- Default ONNX Runtime telemetry off before loading local speech dependencies
  to prevent a native shutdown hang after successful transcription. Explicit
  caller settings are preserved; configure the setting before initializing
  ONNX Runtime in an embedding application.

## Scene exports and canvas changes

- Keep fractional-frame scene boundaries on the authored movie clock rather
  than accumulating each scene's encoded rounding. Explicit-frame-rate exports
  use one final frame grid; video duration can still round up by less than one
  frame. Authored ranges are preserved.
- Switch existing scene compositions between portrait and landscape without
  breaking history validation. Undo restores the prior canvas, layout, and
  coupled edits while retaining earlier history and integrity checks.
- Compare the two requested source frames for camera-hold warnings, instead of
  accidentally averaging in later frames. Valid negative similarity scores are
  retained. Findings remain advisory, with the existing threshold unchanged.

## Text and screenshots that match the edit

- Wrap overlay text using the selected font's shaped advances instead of a
  fixed character-count estimate. Explicit line breaks and whole words are
  preserved; screenshot, watch, and export share the same plans. Unsupported
  fonts report an estimated fallback, and ink/vertical bounds remain estimates.
- Scale manual overlay presets with the render canvas so smaller exports keep
  the intended proportions.
- Include stored overlays in flat-project screenshots, matching the edit being
  previewed.
- Render transparent CSS colors as zero-alpha black rather than an unsupported
  FFmpeg color token.
- Explain the boolean `find --source` flag when an argument error suggests it
  was mistaken for a source selector.

## Account and service compatibility

This package also contains maintenance for the existing account and Cloud
metadata workflows: conditional-upload recovery without overwriting accepted
bytes, automatic durable project-creation retry keys, discovery of accepted
shared project metadata where advertised, references to existing ready account
assets across owned projects on supporting services, and a website link for key
settings. Asset-reference operations require the advertised service capability;
they do not upload originals or grant remote editing. Project reads retain the service's owner/viewer role; viewer metadata access
does not grant media access, editing, rendering, or resharing.

API-key and hosted MCP documentation has been updated. Those endpoints deploy
separately from the Python package and remain subject to account authorization
and service-advertised capabilities. This package release does not establish
availability of remote media editing or rendering, and the distributed plugin
remains skills-only with no MCP server configuration.
