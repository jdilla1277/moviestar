# Create private account assets — Moviestar v0.8.4

Moviestar v0.8.4 adds `moviestar cloud assets create FILE` to upload an original
to your connected account. The package and skills-only plugin share version
0.8.4.

## Upgrade and connect

```sh
python -m pip install --upgrade 'moviestar==0.8.4'
moviestar --version
moviestar account status
```

If disconnected, run `moviestar account connect you@example.com`, approve the
connection in the email, then run `moviestar account status` again. The upload
uses that approved installation; it does not require a personal API key.

This journey needs the base package only, with Python 3.10 or newer. It does
not require FFmpeg, transcription dependencies or a local editing workspace.
For local speech recognition, install `moviestar[transcribe]==0.8.4` instead.

## Upload, find and reopen

```sh
moviestar cloud assets create ./photo.png
moviestar account open
```

A successful upload returns structured JSON with `status: "ready"`, the asset
ID and the upload ID after server validation. Use the account website's asset
library to open and download the same private original. On services advertising
the account-asset catalog, `moviestar cloud assets list` lists ready originals. Uploading does not
create a project reference or share link. Each original uses the account's
existing shared allowance; the service enforces format, file-size and storage
limits.

Starter formats cover videos (MP4, MOV, WebM), audio (MP3, WAV, M4A, FLAC),
images (JPEG, PNG, WebP, GIF) and UTF-8 captions/transcripts (SRT, VTT, TXT).
Content validation remains authoritative; changing a filename does not convert
a file. See [account assets](../account-assets.md) for supported codecs and limits.

## Retry without duplicating the original

Save the generated retry key printed to stderr, or supply one deliberately:

```sh
moviestar cloud assets create ./photo.png --idempotency-key photo-original-1
```

Retry the unchanged file and the same key after an uncertain outcome. If the
transfer already succeeded, retry completion with its upload ID:

```sh
moviestar cloud assets create ./photo.png --resume UPLOAD_ID
```

Recovery preserves the same asset identity. Invalid content, insufficient
capacity, revoked installations and unsupported services return structured
errors and next-step hints rather than claiming success.

The existing project catalog, asset references, conditional project rename,
private developer guides and local editing commands remain available. The
older `moviestar upload` command remains the separate finished-video workflow.
The distributed plugin remains skills-only; hosted MCP deploys separately.
