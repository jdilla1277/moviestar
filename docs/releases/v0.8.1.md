# More reliable edits and explicit review — Moviestar v0.8.1

Moviestar v0.8.1 fixes audio placement and font-rendering defects reported after
v0.8.0, adds practical review exports and evidence tracking, and improves the
sharing and Cloud CLI workflows. The package and skills-only plugin share the
same version.

## Upgrade and installation migration

For local editing **with speech recognition**, install the explicit
transcription extra:

```sh
python -m pip install --upgrade 'moviestar[transcribe]==0.8.1'
moviestar --version
moviestar doctor
```

For account/Cloud metadata commands, or local editing with supplied captions or
`--no-transcribe`, install the lightweight base package:

```sh
python -m pip install --upgrade 'moviestar==0.8.1'
```

**New base installations no longer install the local Whisper/PyAV stack.**
`load` still requests transcription by default when audio is present. Without
the extra it returns structured installation guidance before replacing a
workspace or downloading a model; it does not silently skip speech recognition.
Silent inputs still load without the extra, including with `--no-download`.

Existing environments retain their installed dependencies when upgrading.
Create a fresh virtual environment to obtain a minimal base installation.
The `diarize` extra continues to include transcription, and the `av<19`
compatibility constraint is retained. Installing extras alone does not run or
download a model. See [installation profiles](../installation.md).

## Audio and font fixes

- Preserve delayed external-audio placement instead of collapsing delayed
  passages into the opening and leaving silence later.
- Report final encoded true-peak compliance independently of integrated LUFS.
  A loudness target being met does not imply that the peak ceiling was met.
  Overshoots are reported; this does not add an automatic limiting mode.
- Register readable macOS system fonts without copying protected filesystem
  flags or metadata.
- Render scalable font outlines instead of unsupported bitmap strikes, fixing
  cases such as Geneva at caption sizes. Remaining unsupported bitmap errors
  include actionable font details rather than a generic rendering failure.

## Review copies that fit the delivery route

```sh
moviestar export --review --max-bytes 20000000 --out review.mp4
moviestar watch --from 12 --to 20 --review --max-bytes 5000000
```

The shared review profile fits inside a landscape 1280×720 or portrait 720×1280
box without upscaling. Composition and text are authored at their original
canvas size, then resized; caption wrapping and layout stay intact.

An optional byte limit allows at most two compression retries, preserving the
chosen resolution and final encoded audio. MovieStar measures the final file
after audio processing and returns `size_budget.met`. An unmet limit returns a
nonzero exit and preserves a complete output; request a shorter clip or larger
limit. Compression and byte compliance do not establish visual approval.

Watch retains its existing source-time versus composition-time behavior. Use
export to review the complete edited source when there is no scene composition.
See [review exports](../review-exports.md).

## Separate evidence from approval

```sh
moviestar export --review --review-report --out review.mp4
# Use the returned review_report.out as REPORT.json:
moviestar review show --report REPORT.json
```

Opt-in reports bind to the exact artifact and project state. Technical checks,
source alignment, visual inspection, motion review, and listening start
unreviewed and remain separate. Record the actual reviewer, method, limitations,
and playback ranges or sampled instants with `review record`.

A sampled frame cannot establish full-timeline, motion, or listening review.
Unavailable listening remains explicit; ask a capable reviewer or the human to
listen. Changed media/project state makes evidence stale. Intact active
rejections remain visible until explicitly superseded, including when another
entry's proof becomes stale. Judgments are caller-reported assertions, not
automatic perception checks or authenticated approvals. See
[review evidence](../review-evidence.md).

`moviestar captions audit` also reports authored caption visibility states,
short flashes, gaps/overlaps, and optional bounded proof frames. Connector-word
checks require an explicit language or word list; no language is assumed.
Findings are advisory, and estimated geometry does not establish visual quality.
See [caption timing audit](../caption-audit.md).

## Sharing and account workflows

- `account open` can request a browser sign-in email, and CLI status includes
  hosted plan/capacity information.
- `shared videos` discovers accepted videos shared with the connected account;
  `shared download VIDEO_ID --out FILE` downloads a selected finished cut.
- `shares replace VIDEO_ID FILE` can replace the cut behind existing links
  when enabled by the service, with status, resume, and cancellation commands
  for uncertain outcomes. The original stays available until a valid
  replacement commits, subject to revocation/deletion rules.

These capabilities depend on the connected service and account access. A
download contains the finished MP4, not its sources or edit history. See
[sharing and download](../sharing.md).

## Personal Cloud project metadata

```sh
moviestar cloud capabilities
moviestar cloud projects create "Highlights" --idempotency-key highlights-1
moviestar cloud projects list
moviestar cloud projects show PROJECT_ID
```

The base installation supports these metadata commands without FFmpeg or a local
transcription stack. Service enablement and a human-approved account connection
are still required. Creating metadata does not upload media, select a local
workspace, or promise remote editing/rendering operations; inspect the service's
advertised capabilities. See [personal Cloud projects](../cloud-projects.md).

Local media editing still requires FFmpeg and ffprobe. Python 3.10 or newer is
required, and Moviestar remains licensed under Apache License 2.0.
