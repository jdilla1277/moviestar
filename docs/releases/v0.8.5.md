# Trust the frame. Keep the ending. — Moviestar 0.8.5

This release makes timestamps describe the frames agents actually receive and
preserves the ending picture when replacing audio. It also brings the merged
Cloud editing and access commands into the released CLI: inspect an edit, save
or undo a bounded trim, request an exact-version preview, and retrieve its
verified output on enabled services.

## Upgrade and compatibility

```sh
python -m pip install --upgrade 'moviestar==0.8.5'
# For local speech recognition:
python -m pip install --upgrade 'moviestar[transcribe]==0.8.5'
moviestar --version
```


The package and skills-only plugin share 0.8.5. Python 3.10+ remains
required. The base package supports Cloud commands, supplied captions and
`--no-transcribe`; install `moviestar[transcribe]` for local speech recognition.
Local media work still needs FFmpeg and ffprobe. Existing local projects open
without a migration.

Inspection integrations must handle decoded frame identities: `requested_timecode`
and `timecode` describe different clocks. Prepared thumbnail timing caches are
regenerated. Old saved Cloud jobs retain their original metadata; they are not
relabeled or recomputed. A client upgrade does not change an installed Cloud
engine or enable a disabled service operation.

## Accurate frames, clocks and endings

- Dense inspection and prepared load/skim thumbnails previously inferred source
  time from the sample ordinal. They now identify the decoded source frame,
  preserve its actual presentation timestamp and distinguish that from the
  requested sample position. Sparse/held frames and nonzero starts are covered.
- Watch responses now explicitly identify the source/result clock and selected
  source. A flat project watch remains source-time even after trimming;
  composition watches use result-time. This changes disclosure, not extraction.
- Millisecond timecode rounding now carries across minute/hour boundaries.
  Durations near 59.9996 and 3599.9996 seconds format as `0:01:00.000` and
  `1:00:00.000`, with matching rounded numeric seconds.
- Replacing audio could discard the final reordered H.264 picture packets on
  FFmpeg 9. The shared audio post-pass now drains copied video through EOF while
  its filtergraph keeps audio bounded to the authored range. Video is neither
  padded nor re-encoded by that pass; fast-trim keyframe limits remain visible.
- Reloading a project with changed supplied captions now refreshes its imported
  transcript without replacing authored caption overlays.
- Portable origin metadata can travel with an existing saved spec without
  pretending it is a media hash, a new Cloud asset or a verified copy.

## Read, save and render an exact Cloud edit

- Discover editing capabilities, read an initial timeline and dry-run a trim
  against the existing public engine. Original, source and project-reference
  identities remain distinct; validation does not prove media-byte integrity.
- On enrolled services, save and reopen immutable one-video trim revisions and
  undo a saved operation. Apply/recover retains the exact request, revision and
  retry key after an uncertain response. Abandoning pending local recovery does
  not cancel or prove rollback of a possible server save.
- Submit a preview for an explicit saved revision, follow its job through
  rendering/independent verification, and retrieve the verified MP4. Downloads
  check size/SHA-256 and do not overwrite files or send account credentials to
  storage. An old output remains tied to the edit version that generated it.
- Initial preview limits: one owned ready MP4, trim-only instructions, at most
  30 seconds of result, 64 MiB input and 16 MiB output. Account enrollment,
  current authority, service capabilities and quotas are still required.
  Independent decoding is not human viewing/listening.
- The client also accepts `--kind final` for full-quality output of the same
  explicit saved revision. Where separately enabled/enrolled, the bounded
  profile supports one owned square-pixel MP4, trim-only state, <=30 seconds,
  <=1920 pixels on either edge, <=64 MiB input/output and the native x264 full
  profile. Preview and final have separate retry identities. Mixed audio,
  layouts and captions remain outside these personal profiles. Client support
  does not establish Production final activation; check capabilities first.

```sh
moviestar cloud edits capabilities
moviestar cloud edits show PROJECT_ID
moviestar cloud renders submit PROJECT_ID --revision REVISION_ID --kind preview
moviestar cloud renders show PROJECT_ID JOB_ID
moviestar cloud artifacts download PROJECT_ID ARTIFACT_ID --out preview.mp4
```

## Manage account access and originals

- Inspect account storage, monthly Cloud allowance and grouped Activity from the
  remote CLI. Task/attempt accounting stays separate from actual provider costs;
  local work does not consume Cloud allowance.
- Discover, review and explicitly accept received project/asset invitations from
  the CLI. Owner/editor/viewer permissions stay distinct; access is rechecked.
- Manage project editor invitations and roles. Recipients can explicitly leave
  a received asset/project share without revoking independent access paths.
- Download one accessible original with `cloud assets download`; deletion is a
  separate, owner-confirmed operation. A deletion receipt distinguishes ended
  access, pending cleanup and actual storage allowance release.
- Connect a developer-controlled CLI with an explicit personal API key. Keep
  the chosen origin/profile deliberate; keys are never inferred from media.
- Invitation creation now distinguishes a retained invitation from email
  notification delivery or suppression. Missing notification does not mean
  the invitation was not created.

## Reliability and scope

Ubuntu package CI now uses bounded, verified FFmpeg downloads and a reusable
package cache instead of repeatedly depending on an unbounded apt update.

This cut contains the 24 public merges from v0.8.4 through `3ed226c`.
The saved-mix, transcript-import and Spatial scene-format PRs are not included.
The new sharing and feedback walkthroughs describe unlisted-link permissions,
connected account contact, explicit anonymous submission and uncertain retries.
See [sharing](../sharing-guide.md) and [feedback](../feedback-guide.md). The exact-revision render example under `examples/` is a local
mock, not deployment or account availability evidence. Hosted MCP and installed
workers deploy separately from the PyPI package. Cloud functionality remains a
developer preview; consult current capabilities before invoking it.
